============================================================
7. DEVELOPMENT WITHOUT CENTRAL DATABASE
============================================================

Design/implement the development profile so Architecture AI does not become unusable merely because OpenShift development has no central database.

Preserve this hierarchy:

Git
= declarative/governed definitions and reconstructable inputs.

Local/embedded stores
= current workstation mutable state and projections.

OpenShift DEV without central DB
= Git-derived declarative/read projections + explicitly temporary/degraded mutable runtime state.

Future central DB
= selected mutable/shared authority after migration analysis.

Do NOT use Git as a high-frequency transactional database.

Expose an explicit capability/health state equivalent to:
`DEGRADED_NO_DURABLE_RUNTIME_STORE`.

The service should start and expose feasible read/Director capabilities even in the worst-case dev profile.
