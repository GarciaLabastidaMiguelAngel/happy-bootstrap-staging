# Change Impact Assessment Template

Status: ACTIVE_TEMPLATE
Purpose: prevent active Devin sessions from continuing against obsolete direction or incompatible shared contracts after a material change.

## Change metadata

- change_id:
- previous_direction_revision:
- new_direction_revision:
- previous_repository_baseline:
- new_repository_baseline:
- change_type:
- rationale:
- accepted_by:
- accepted_at:

## 1. Material change summary

Describe the change in bounded terms.

## 2. Why it is material

Classify affected dimensions:

- product shape
- operating mode
- runtime/deployment
- storage/repository authority
- protocol strategy
- agent/session/work model
- event/saga model
- observability/audit
- security boundary
- build/runtime baseline
- shared contract/schema
- dashboard/control-plane behavior
- other

## 3. Affected contracts and surfaces

List exact contracts, modules, configuration, migrations, DTOs, manifests or shared surfaces affected.

## 4. Active prompt/session impact matrix

For every active prompt/session classify:

- UNAFFECTED
- REVIEW_REQUIRED
- PAUSE_REQUIRED
- SUPERSEDE_REQUIRED

Record:

- prompt/session ID
- current repository baseline
- owned scope
- affected assumptions
- required action
- context refresh required YES/NO

## 5. Compatibility assessment

Classify each relevant interface/change:

- BACKWARD_COMPATIBLE
- CONDITIONALLY_COMPATIBLE
- BREAKING
- UNKNOWN_REQUIRES_VALIDATION

Do not infer compatibility from naming alone.

## 6. Deterministic checks

List checks required to prove impact, such as:

- build/test
- architectureCheck
- schema validation
- API contract diff
- migration compatibility
- telemetry contract validation
- replay/simulation
- provider/API validation

## 7. LAB evaluation

When useful, evaluate the change using LAB evidence.

Possible methods:

- deterministic scenario comparison
- replay
- Monte Carlo for explicit uncertainty
- queue/capacity model
- reliability/failure impact
- semantic/vector drift signal

Always classify inputs as OBSERVED, SIMULATED, ASSUMED or EXPERIMENTAL.

A vector similarity score is advisory evidence, not an acceptance decision.

## 8. Required session notifications

For each impacted session create a bounded Change Notice containing:

- what changed
- why
- new direction revision/ref
- what remains valid
- what is invalidated
- affected assumptions
- exact review/rework requested

Sessions must not be expected to infer major direction changes from Git history alone.

## 9. Acceptance outcome

- ACCEPTED_NO_SESSION_ACTION
- ACCEPTED_CONTEXT_REFRESH_REQUIRED
- ACCEPTED_PAUSE_ACTIVE_WORK
- ACCEPTED_SUPERSEDE_ACTIVE_WORK
- REJECTED
- DEFERRED_PENDING_EVIDENCE

## 10. Follow-up work

List research, engineering, validation or reconciliation work generated by this change.
