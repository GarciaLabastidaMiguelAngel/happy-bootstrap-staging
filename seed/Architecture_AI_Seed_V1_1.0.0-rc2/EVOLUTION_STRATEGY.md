# Evolution Strategy

## Governing cycle

`OBSERVATION → GAP/OPPORTUNITY → IMPACT ANALYSIS → PROPOSAL → SPEC/SKILL/COMPONENT/PLAN CHANGE → VERIFICATION → NEW CANONICAL VERSION`

Never use `OBSERVATION → MODIFY CANONICAL STATE`.

## Direction

- **NOW:** preserve/reconcile Seed identity, evidence, implementation baseline and eligible work.
- **NEXT:** recover the organizational repo/runtime, exact Skills/Tools and verification; expand only source-supported capabilities.
- **LATER:** centralized/OpenShift operation, richer Graph/RAG, multi-agent planning, Harness/Loop automation, UX and governed ML use cases.
- **CONDITIONAL:** deterministic migration after stable agentic behavior is evidenced; external technology only after corporate-capability and standards fit analysis.
- **EXPERIMENTAL:** ML/LLM capabilities require a non-AI baseline and evaluation/promotion gate.
- **REJECTED:** arbitrary self-modification, blind retries, newest-version-by-default, custom semantics without gap evidence.

## Federated and human evolution

- Observe/model before agreed integration; never `observe→replace`.
- Preserve domain owner/authority and justified local variants while sharing architectural intelligence.
- Evaluate deterministic migration through Harness/shadow/equivalence/rollback evidence.
- Treat human-value shift as an authority-gated proposal: automation should redirect repetitive effort toward policy, judgment, knowledge and capability evolution, not assume team elimination.
- Domain Context/UX surfaces remain projections of one governed model.
